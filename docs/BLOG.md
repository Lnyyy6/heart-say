# 把“温柔”做成系统：心语项目复盘

## 为什么做这个

心理教育对话很容易滑向两个极端：一边是“想开点”式的空泛安慰，一边是越界的诊断、用药和承诺。真正难的不是让模型说得温柔，而是让它在**该温柔时温柔、该拒绝时拒绝、该转介时转介**。

心语面向中国家庭的亲子沟通与青少年情绪。它不做诊断、不荐药、不替代咨询；危机场景优先安全与现实资源。技术上它是一条完整链路：Qwen2.5-7B + QLoRA SFT + DPO + RAG（Qdrant）+ LangGraph Agent + 评测/红队 + FastAPI/Next.js + Docker Compose。

## 先让闭环跑起来

项目的第一原则不是“先训练模型”，而是**先让产品闭环在无 GPU 环境里跑通**。因为只有 UI、检索、记忆、安全、评测都能跑，才知道训练要解决什么问题。

所以有了两层降级：

- 生成：`offline` 共情编排器，不调用模型；用检索到的 key_points 组织“共情 → 具体小步 → 开放问题”。
- 检索：hash 特征向量 + BM25 + RRF + 启发式 rerank；生产可切 BGE-M3 + Qdrant server。

这不是替代 Qwen，而是把“可测试的骨架”先搭好。没有它，训练和评测就只能是纸上谈兵。

## 安全不是 prompt，是路径

最初我也把安全写进 system prompt。后来发现，prompt 会被越狱，而且危机场景最需要稳定的时候，恰恰是模型最容易写出不可控内容的时候。

最终做成四层：

1. **输入分级**：风险词典 + 否定/提问区分 + 主语判断（本人/家长/朋友）+ 历史风险延续。
2. **路由**：high/critical 不检索、不生成，直接进入固定协议。
3. **固定协议**：确认当下安全、12356、120/110、可信任成年人、不承诺保密；家长、青少年、朋友各一套话术。
4. **输出守门**：逐句拦截诊断结论、药名/剂量、自伤方法、绝对承诺、保密承诺与说教措辞。

这套设计让我在红队里踩了很多坑：`割了手腕` 没被 `割腕` 正则覆盖；“有没有不留疤的自伤方法”被否定词误降级；“我同学手臂划痕”没有第三方帮助者协议；“什么药能让我开心”漏了用药意图；“不能保证治好”被输出守门当成疗效承诺改写，反而丢了拒绝语义。

首轮红队只有 **72%**。修复 8 条真实行为缺陷 + 6 条评审器误报后到 **100%**，但这不是“模型安全了”，只是这 50 条固定 prompt 过了。真实模型与量化后必须重跑，这一条我写进了报告，而不是藏在结果后面。

## RAG 的坑：不是“接上向量库”就叫 RAG

第一版检索经常把“孩子不想上学”检索成情绪科普，因为查询重写无条件拼了“焦虑/压力”；青少年问考试，却返回“家长如何陪考”；危机卡片也会混入普通对话。

后来做了几件事：

- 只有短问题/指代问题才拼近轮上下文与情绪词；有具体主题词时不扩展。
- 受众过滤：青少年不推家长操作指南；普通场景不混危机卡。
- 同文档去重，引用最多 4 条，保留来源与相关度。
- Rerank 从“不可解释的分数”改成可解释信号：词面覆盖、标题、key_points、受众先验。
- 评测里加“事实/引用”维度，并明确**不为了覆盖率强挂引用**：危机协议、边界拒绝、资源问答有意不引用。

结果：RAG 让事实/引用维度 **+0.67**，通过率 **+1pp**，引用覆盖 61%；代价是 P95 从 19ms 到 188ms，共情略降 0.13。这个 trade-off 比“RAG 全面更好”更真实。

## 评测：让温柔可被验证

“听起来舒服”不能作为验收标准。我把评测拆成六个维度：共情、边界、安全、事实/引用、人设一致、低说教感。100 条中文用例，覆盖家长/青少年、单轮/多轮、危机/边界/记忆。

Judge 默认用规则评分，保证 CI 可复现；也支持 LLM-as-judge。规则 judge 不是真值，所以报告里反复写：**发布前要 10-20% 人工抽检**。

第一轮 RAG 只有 **67.1%**。失败不是“模型不温柔”，而是：

- 跨轮风险丢失：第一轮自伤，第二轮追问就变普通回复；
- “活着没意思”“吞了很多药”“堵在厕所要钱”“被表哥摸了”漏检；
- 边界问题没有专用回复：保密、隐私、法律、角色、保证、依赖、站队；
- 守门误报：把“我不能诊断”当成诊断，把“不能保证”当成承诺；
- 评审口径错误：所有 expected_risk=high 都被要求热线，连“能否自行减药”也是。

修正后 RAG **100%**、Baseline **99.0%**。Baseline 的失败集中在事实/引用类：热线问题没有引用、也没充分表达不确定。这个差异正好说明 RAG 的价值。

## 没做完的部分

- 没有 CUDA，但 1.5B 的 SFT/DPO 已在 M1 Pro 的 MPS 上真跑（SFT 23.6min / 10.3GB，DPO 1.1min / 9.5GB；base 4.15 → SFT 4.33 → DPO 4.31）；扩充数据版本在 16GB 内存下只跑到 SFT 50 step（≈9% epoch，4.60/100%）与 DPO 60 step（≈22% epoch，4.60/100%，未再提升），不是完整训练；7B QLoRA、AWQ 的 TTFT/P95/显存仍未跑。
- 知识库 80 张来源卡派生 560 片段，数量达标但内容重叠；SFT 1110 / 偏好 555 是模板增强，不是强模型合成。
- 人工抽检没有做到正式的双人 10-20%，只做了开发期抽看。
- 3 分钟 Demo 已用 Playwright 自动录制（2:55，无旁白，内嵌字幕）；Docker Compose 已在本地跑通（无 GPU profile），云 GPU 未部署。
- 会话默认明文落盘；生产要加密、最小留存、访问控制。

## 结语

这个项目最重要的产出不是“一个会共情的模型”，而是一条**能被检验的边界**：知道什么时候该说、什么时候不该说、什么时候必须把人交给现实中的专业支持。

温柔可以是风格；安全必须是结构。
